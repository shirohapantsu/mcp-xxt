## 1. 项目概述

把 ocsjs（fork，vendor 于 `mcp-xxt/ocsjs`）改造为 MCP server 驱动的学习通**流程化答题**系统：

1. 保留自动答题流程（题目抓取 → 作答 → 暂存/提交），**题库搜题替换为 MCP 拉取式协议**（agent 出答案）；
2. 刷课功能（视频/文档/阅读/倍速）**硬禁用**，自动跳转框架保留作为课程导航骨架；
3. 整个流程封装为 MCP 工具（stdio），MCP 是唯一自动化入口（原 xuexitong 技能已卸载，后续重写为 MCP 客户端）。

**v1 范围**：仅超星学习通（cx）；主域（chaoxing.com / xueyinonline.com）验收，学校壳域名 best-effort 不进验收矩阵；**章节测验全自动**，作业/随堂练习只到"答案填入 + 人工保存"；**考试场景暂不测试**。

## 3. 系统架构

```
┌─ Agent（ZCode / Claude / 重写后的 skill）────────────────────┐
│ 课程遍历模式（主）：open_login → open_page(课程学习页)        │
│   → wait_next_work ↻（取题→作答→审核→submit_paper）           │
│   → course-finished / traversal-blocked 终止                 │
│ 手动模式：open_page(作业URL) → start_work → 同一答题轮        │
└──────────────┬───────────────────────────────────────────────┘
               │ MCP (stdio, @modelcontextprotocol/sdk；日志走 stderr)
┌──────────────▼───────────────────────────────────────────────┐
│ server（独立 TS 项目，mcp-xxt/server）                        │
│  工具层(11 个)                                                │
│  run-manager：状态机 + 权威 deadline(300s) + 事件信封/游标   │
│    + 单 run 互斥 + 重进计数(按 job 身份,进展即重置)          │
│  登录：账号密码自动尝试 → 验证码转人工（截图返回）             │
│  Playwright：chromium 有头 + 持久 profile + 每导航注入 bundle │
│  通信：context.exposeBinding('__mcpEvent') ← 各 frame 事件    │
│        （含来源 page/frame，绑定 run_id + frame 身份 + 代次） │
│        frame.evaluate → 回填答案 / 下发指令                    │
└──────────────┬───────────────────────────────────────────────┘
               │ 注入 IIFE bundle（bootstrap：shim+模式标记→frame 桥→bundle→框架启动）
┌──────────────▼───────────────────────────────────────────────┐
│ ocsjs fork（entry-mcp 模式，页面主世界运行）                  │
│  GM shim（localStorage 后端 + 通知 shim：本frame分发+广播） │
│  媒体硬禁用（全入口守卫，先于框架生命周期）                   │
│  跳转框架 = 主导航（searchJob/getNext/mode='next'）           │
│  chapter() → work-detected（确认制）→ MCP answerer            │
│    （队列 + await server 回填）→ SearchInformation[]          │
│    → 题型匹配器（Worker 调度层改造，F11）                     │
│  章节测验适配器（save/submit 接状态机）；其余场景能力标志      │
│  easy-us 悬浮面板保留（人类监督窗）                           │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 通信协议（server ↔ 页面）

- **上行（页面 → server）**：`__mcpEvent(type, payload)`，经 `exposeBinding` 回调，server 从回调取得来源 frame。事件类型：
  - `work-detected`（需 server 回执确认后 frame 才注册题目）；
  - `question`（题目入队）、`question-result`（逐题应用结果：`applied` / `applied-failed` / `timeout` / `skipped` / `unsupported`）；
  - `work-completed`（worker doWork 整卷作答结束，带 frame 代次——**ready_for_review 的唯一迁移依据**）；
  - `course-finished` / `traversal-blocked` / `page-invalid`、`log`。
- **下行（server → frame）**：`frame.evaluate` 调用 frame 本地桥——回填答案、下发 deadline/取消 signal、读取状态。
- **事件信封**：两类——遍历级事件（`session_id` + 单调 `event_id`，允许无 run_id，如 work-detected 自身、无测验课程的 course-finished）；run 级事件（额外绑定 `run_id`）。均含 frame 身份与 document 代次。
- **消费规则**：server 保存事件历史并按 **per-session 游标**投递——每个事件至多投递一次，`wait_next_work` 隐式自上次投递处续读（超时/重试不消耗未交付事件）；`wait_next_work` 支持可选 `request_id`，重试携带同一 id 返回**缓存响应**（客户端超时/取消不跳过当前事件，"写出响应"≠"已处理"）；**未终态活跃 run 可经 `get_status`（缺省当前）重新发现**（事件丢失的自愈兜底）；已结束 run 的旧 work-ready 不抢占下一轮等待；`open_page(课程页)` 创建并返回 `session_id`，重开课程时旧 session 的 waiter 终止、迟到事件忽略、新 session 不继承。

### 3.2 run 状态机（D13/D19）

```
running ──逐题 applied/applied-failed/timeout/skipped/unsupported 齐 + work-completed──▶ ready_for_review
ready_for_review ──submit_paper(temporary)──▶ saving ──成功──▶ saved
  ├─ 手动模式：saved 页面仍占用，可再 submit_paper(confirm)
  └─ 课程模式：saved 即标记预期导航 → saved-and-left（终态：释放互斥、继续遍历、不可再 confirm）
ready_for_review / saved（手动）──submit_paper(confirm)──▶ submitting ──▶ finished（终态，释放互斥）
saving 失败 ──▶ 退回 ready_for_review（保留重试入口，run 不终态）
submitting 结果不确定（超时）──▶ 先 readResult 核验，禁止盲目重复提交
任意状态 ──abort_run(reason?)──▶ aborted（异常）/ released（reason:'manual-saved'，人工保存完成）（终态）
frame 分离 / 页面失效 ──▶ aborted（终态）
```

- **ready_for_review 条件**：全部题目到达终态（applied / applied-failed / timeout / skipped / unsupported）**且**收到 `work-completed`；匹配失败进入可审核的明确失败状态，不让 run 卡死；`submit_paper` 前校验页面侧无未结束的填答任务。
- **能力标志拆分**：`auto_save` 与 `auto_submit` 分开报告；不支持的 mode 返回结构化 `unsupported` 并保持 run 状态不变。
- 单活跃 run 互斥（存在未终态 run 时 start_work / work-detected 报错；`finished` / `saved-and-left` / `released` / `aborted` 均为终态，释放互斥）。
- 重复提交、超时回填、已离开页面的调用返回明确错误。

## 4. MCP 工具规格（11 个）

| 工具 | 输入 | 返回 / 说明 |
|---|---|---|
| `open_login` | — | `{status:'ok'\|'need-human'\|'failed', screenshot?}`；自动尝试配置的账号密码；验证码/风控转人工 |
| `get_login_status` | — | `{loggedIn: boolean}` |
| `open_page` | `url` | `{url, title, session_id?}` 通用导航；命中课程学习页时创建新遍历 session 并返回 session_id（旧 session 的 waiter 终止、迟到事件忽略） |
| `start_work` | — | `{run_id}`。**手动入口**（独立作业页）；已有活跃 run 报错；页面不匹配报错 |
| `wait_next_work` | `timeout_s`（默认 60）、`request_id?` | `{event:'work-ready', run_id, session_id}` \| `{event:'still-waiting'}`（幂等重调，不消耗未交付事件）\| `{event:'course-finished'\|'traversal-blocked'\|'page-invalid', reason?, session_id}`。按 §3.1 游标续读；重试携带同一 request_id 返回缓存响应 |
| `get_status` | `run_id?`（缺省当前） | run 状态 + 逐题 `[{id,type,title,answer?,status,resolved,finish}]`（status: pending/answered/applied/applied-failed/timeout/skipped/unsupported）+ `capabilities:{auto_save, auto_submit}`；审核单数据源 |
| `get_pending_questions` | `run_id` | 工具结果**顶层 content 数组**放 image block，题目元数据在 `structuredContent.questions:[{id,type,title,options?,images?}]`；**空 pending ≠ 完成** |
| `submit_answer` | `run_id, question_id, answer` | answer 见 §4.1 |
| `submit_answers` | `run_id, [{question_id, answer}]` | 批量版 |
| `submit_paper` | `run_id, mode:'temporary'\|'confirm'` | `saved` / `saved-and-left`（课程模式）/ `finished`；能力不足返回结构化 `unsupported`（保持 run 状态）+ 人工保存提示；saving 失败退回 ready_for_review；submitting 不确定先 readResult 核验；提交成功以响应/页面结果确认 |
| `abort_run` | `run_id, reason?`（如 `'manual-saved'`） | 终止 run：取消所有等待、传播取消 signal 终止 DOM 写入；reason='manual-saved' 终态记 `released`，否则 `aborted` |

### 4.1 答案 schema（D15）

| 题型 | answer 格式 | 兼容层 |
|---|---|---|
| 单选 single | 选项文本 **或** 字母（`"A"`） | core `resolveSingle`（ABCD 兜底天然兼容） |
| 多选 multiple | 选项文本数组拼接字符串 **或** `"ABD"` | `resolveMultiple` + `splitAnswer` |
| 判断 judgement | 对/错文本（`√/×/T/F/对/错/正确/错误` 均识别） | `resolveJudgement` 关键词表 |
| 填空 completion | `string[]`（每空一项）或单 string（按分隔符拆） | `resolveCompletion` |
| 连线/完形/阅读 | **v1 unsupported**：跳过不改 DOM，`get_status` 显示"未作答（题型不支持）" | — |

**300s 计时语义**：从题目入队（work-detected 确认后注册）起计时；agent 是否已取题不影响计时；`aborted` 终止一切计时；超时题标记 `unanswered-timeout` 并继续流程。Worker 内部的 70s 派生超时在 MCP 模式失效（F11）。

**输入编码（D19/D20）**：`SearchInformation.answer` 为 string（worker 侧会 trim），数组不可直接传入——工具层做确定性编码：填空 `string[]` → **`JSON.stringify` 编码**（复用 `splitAnswer` 既有的 JSON 解析分支，无损还原；分隔符 join 会丢失答案边界，如 `["C#"]` 被静默错填，已废弃）；纯 string 输入语义 = 按分隔符表达多个答案（与原题库一致），**单空且答案文本含分隔符时必须用 string[]**（server 按 blankCount 预校验，违规返回结构化错误）；空项在工具层拒绝。多选"选项全文拼接"输入为 string。选项顺序 = `get_pending_questions` 返回的 options 顺序，字母序（A–N）由此确定。兼容验证四类：双空填空数组、含分隔符单空、多选纯字母、多选选项全文。

| F11 | Worker 调度层 + 取消传播 | `packages/core/src/core/worker/worker.ts`、`question.resolver.ts`、cx handler | 最小 diff 守卫点：① deadline 参数化（server 下发，MCP 模式 70s 派生超时失效）；② 每次异步等待后、DOM 写入前复查取消；③ close/abort 统一终止等待中的作答；④ **取消 signal 经 WorkContext 传入**——resolver 的 DOM 包装层每次 `handler` 调用前检查（多选逐项循环间）、cx handler 每次点击/填写等异步步骤后检查、onResultsUpdate 后处理同样受控；四种纯匹配函数保持复用；区分"取消发起"与"旧任务已停止写入"（后者完成前旧 run 延迟回调不得干扰新 run）。cx 各 worker 补启 rootObserver（ADR-0016/0020） |

其他 5 平台源码保留不动；上游同步走 fork git rebase。

### 8.2 验收矩阵（两轮评审要求的场景）

等待超 70s 回填 ✓（P2）；等待中 abort/页面刷新/frame 分离/重复回填 ✓；ready_for_review 晚于最后一题 DOM 写入（question-result/work-completed 时序）✓；已完成测验重进（快速跳过）；锁定课程（traversal-blocked 可诊断）；**同章节多个不同测验不误判 blocked**（计数身份化）；媒体配置手动打开仍不执行（P1）；**主域内不同子域父/子 frame 的面板与 cors 往返正常（同源 BroadcastChannel + 跨源 server 中继，无静默挂起）**（P1）；保存失败退回 ready_for_review、提交不确定先核验（P2/P3，章节测验）；**填空 JSON 编码四类**（双空数组/含分隔符单空/多选纯字母/选项全文，含 `["C#"]` 不被错拆）（P2）；wait_next_work 客户端超时后重试不跳过事件（request_id 缓存）（P2）；图片题 agent 可见（P4）。
